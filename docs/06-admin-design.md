# 管理端设计

## 1. 管理端定位

管理端用于支撑用户侧 AI 个性化学习体验的稳定运行，负责课程结构、课程资料、模型能力、资源治理和运行监控。

管理端不是用户学习主入口，也不直接承载普通学习对话。它的职责是：

* 建设课程结构；
* 建设课程资料知识库；
* 配置 ChatProvider 和 CloudRagProvider；
* 绑定课程与 AI 能力；
* 审核资源；
* 监控成本、质量、RAG 命中、调用延迟和告警；
* 记录关键管理操作，支持追踪、回放和排障。

管理端需要服务两个目标：

1. 让管理员能稳定配置和治理 AI 学习系统。
2. 让用户侧在模型、课程资料或资源审核异常时得到明确、可信的状态提示。

## 2. 访问控制与管理范围

### 2.1 访问入口

所有 `/admin/*` 路由只允许 `role = admin` 的账号访问。普通用户访问管理端时，应重定向回 `/dashboard`，不得展示管理数据或配置表单。

```text
用户访问 /admin/*
  ↓
AdminGate 检查当前登录用户
  ↓
role = admin：进入管理端
role != admin：重定向 /dashboard
```

### 2.2 管理端职责边界

管理端负责“配置、治理、审核、监控”，不直接替代用户侧学习流程。

| 能力 | 管理端负责 | 用户侧负责 |
|---|---|---|
| 普通 Chat | 配置 ChatProvider、查看调用日志、健康检测 | 发起学习对话、接收回答 |
| 课程资料问答 | 上传资料、配置 CloudRagProvider、检索测试 | 显式选择课程资料问答模式 |
| 资源生成 | 配置模型、审核资源、查看 trace | 触发生成、预览、编辑、保存 |
| 学习路径 | 建设课程结构和知识点 | 学习、标记进度、获取推荐 |
| 学情画像 | 查看画像相关运行影响、排障 | 画像展示、纠偏、学习闭环 |

### 2.3 权限与审计原则

关键管理操作必须写入审计日志，至少包含：

* 操作人；
* 操作时间；
* 操作类型；
* 目标对象；
* 操作前后关键状态；
* traceId；
* 成功或失败；
* 失败原因。

需要审计的操作包括：

* 新增、编辑、删除 ChatProvider；
* 新增、编辑、删除 CloudRagProvider / ChatDoc 配置；
* 测试供应商连接；
* 上传、删除、彻底删除课程文档；
* 批量解析、抽取、向量化；
* 修改课程 AI 绑定；
* 通过、驳回、要求修改资源；
* 标记精选资源；
* 删除或还原课程；
* 导出调用日志或运营数据。

## 3. 管理端路由与信息架构

| 路由 | 页面名称 | 页面定位 |
|---|---|---|
| `/admin/knowledge-base` | 知识大本营 | 课程资料上传、解析、向量化、检索测试、切片预览和引用治理。 |
| `/admin/model-gateway` | 网关中心 | ChatProvider、CloudRagProvider、课程绑定、意图路由配置、用量统计、调用日志和健康检测。 |
| `/admin/resource-review` | 资源审核 | 审核用户提交到资源大厅或社区的资源。 |
| `/admin/operations-monitoring` | 云原生运维舱 | 运行状态、成本、Token、RAG 命中、延迟、告警和事件。 |
| `/admin/course-builder` | 课程建设台 | 课程大纲、章节、知识点、知识元素和课程图谱。 |
| `/admin/announcements` | 公告发布 | 管理顶部条、弹窗、Toast、页面卡片和列表公告。 |
| `/admin/interface-settings` | 界面设置 | 管理登录页背景媒体、预览和视觉参数。 |
| `/admin/chatdoc-config` | ChatDoc 配置 | 兼容入口，用于配置 ChatDoc / 云端 RAG。 |
| `/admin/knowledge-base?panel=recycle` | 回收站 | 查看已删除课程和文档，支持还原或彻底删除。 |

页面之间的主要跳转关系：

```text
课程建设台
  → 知识大本营：上传课程资料、绑定章节资源

知识大本营
  → 网关中心：配置 CloudRagProvider / ChatDoc 凭证
  → 回收站：还原或彻底删除文档

网关中心
  → 运维舱：查看供应商健康、调用失败和成本

资源审核
  → 运维舱 / 调用日志：追踪生成 trace 和安全审查记录

公告发布
  → 用户公告中心 / 顶部条：发布维护、规则、课程和功能通知

界面设置
  → 登录页：更新登录背景、遮罩和回退底色
```

## 4. 管理端通用交互规范

### 4.1 视觉主题与后台风格

管理端后台统一采用 **shadcn/ui New York 风格的极简中性 SaaS 管理台**。这套风格以黑、白、灰为主，强调数据密度、边界清晰、操作效率和工程质感，适合知识库治理、模型网关、资源审核、公告配置、运维监控等高频管理场景。

后续 AI 或开发者新增、重构、优化任何 `/admin/*` 前端页面时，必须优先使用本节规范作为默认后台主题，不得在没有明确需求的情况下另起一套视觉体系。

所有面向管理员可见的页面标题、功能说明、指标卡标签、状态值、按钮、表格列名、空状态和提示文案必须以简体中文为主，不得直接交付纯英文说明。技术字段、协议名、枚举或配置键可以保留英文，但必须配中文语义，例如“当前版本 Active Version”“响应路由 route”“注册表结构规范（Registry schema）”“semantic-router 语义召回”。后续 AI 生成或修改后台页面时，应先检查首屏、侧边栏、表单检查器和关键操作区是否存在 `Active Version`、`Draft`、`Validation`、`Warmup`、`Routing Performance`、`Intent Registry` 等裸英文标签，并改为中文优先文案。

风格关键词：

* **shadcn/ui New York**：低圆角、紧凑控件、清晰边框、轻量阴影；
* **Neutral / Zinc 黑白灰色系**：以 `#FFFFFF`、`#F8FAFC`、`#F4F4F5`、`#E4E4E7`、`#71717A`、`#18181B`、`#09090B` 为主；
* **现代 SaaS 后台**：接近 Linear / Vercel / Notion / Stripe Dashboard 的克制工具感；
* **数据密集型工作台**：表格、筛选、分段标签、状态徽标、抽屉详情和分页是主要界面语言；
* **低装饰、高可读**：减少大图、插画、渐变背景和营销式 hero，避免干扰管理员完成任务。

布局与构图要求：

* 管理端优先采用左侧固定导航 + 顶部或页面内操作区 + 主体工作区；
* 页面第一屏应直接呈现可操作的数据、配置、队列、日志或监控内容，不做营销式欢迎页；
* 主内容区使用细边框容器承载表格、图表和配置面板，边框颜色保持低对比但清晰可见；
* 表格优先支持列控制、筛选、搜索、排序、批量操作、横向滚动、分页和空状态；
* 分段控件用于切换同一业务对象的视图，例如概览、队列、日志、配置、测试；
* 详情信息优先使用右侧抽屉、弹窗或相邻面板，不强制跳转到全新页面；
* 页面可使用少量指标卡，但不要把整页设计成卡片堆叠，页面区块应保持工作台式平铺结构。

组件与视觉细节：

* 圆角以 `6px` 到 `8px` 为主，按钮、输入框、表格容器和弹窗保持一致；
* 阴影只用于浮层、下拉、弹窗、抽屉和少量悬浮工具，不使用厚重投影；
* 主按钮可使用近黑色或深灰底，次级按钮使用白底细边框，危险操作使用红色但保持克制；
* 状态标签使用浅底细边框加小色点或图标区分，例如成功绿色、处理中灰色、失败红色、阻断琥珀色；
* 图标优先使用 lucide 风格线性图标，尺寸保持 `16px` 到 `18px`；
* 表格文字密度应适合后台扫描，行高、字号和间距不要做成展示型大卡片；
* 图表使用单色或少量中性色渐变，保留坐标、刻度、图例和 hover 详情，不使用炫光大屏效果。

色彩使用约束：

```text
页面背景：#F8FAFC / #FAFAFA / #FFFFFF
面板背景：#FFFFFF
表头背景：#F4F4F5 / #F8FAFC
边框线：#E4E4E7 / #E5E7EB
主文字：#09090B / #111827
次级文字：#71717A / #6B7280
弱提示文字：#A1A1AA / #9CA3AF
主操作：#09090B / #18181B
成功状态：#16A34A / #22C55E
失败状态：#DC2626 / #EF4444
警告状态：#D97706 / #F59E0B
信息状态：#2563EB / #3B82F6
```

明确避免：

* 不使用大面积紫蓝渐变、霓虹科技风、深色大屏风、玻璃拟态、拟物风、强插画风；
* 不把后台首页做成品牌营销落地页或满屏 hero；
* 不为了“好看”牺牲表格密度、字段完整性、筛选效率和错误可追踪性；
* 不主动为移动竖屏重排管理端，除非用户明确提出移动端后台适配需求；
* 不使用固定假进度、静态演示数据或无法解释来源的统计数字。

### 4.2 页面布局

管理端页面统一采用 overlay 工作台模式，适合表格、筛选、状态卡片和配置表单。

推荐结构：

```text
页面标题区
  ├─ 标题
  ├─ 页面说明
  ├─ 课程 / 时间 / 状态筛选
  └─ 主要操作按钮

状态指标区
  ├─ 数量
  ├─ 健康状态
  ├─ 失败数
  └─ 今日变化

主体工作区
  ├─ 表格 / 队列 / 图谱 / 配置面板
  ├─ 右侧详情 / 抽屉 / 预览
  └─ 日志 / trace / 事件
```

### 4.3 通用状态

所有管理端异步操作应至少有以下状态：

| 状态 | 含义 | 页面表现 |
|---|---|---|
| idle | 未开始 | 展示可操作入口 |
| loading | 数据加载中 | 骨架屏或加载状态 |
| pending | 已提交，等待处理 | 禁用重复提交，显示等待 |
| processing | 后台处理中 | 展示阶段和进度 |
| success | 成功 | 展示结果并刷新列表 |
| failed | 失败 | 展示错误码、原因和重试入口 |
| blocked | 被前置条件阻断 | 展示缺失配置或权限原因 |

### 4.4 错误提示

管理端错误提示不能只显示“失败”。需要尽量包含：

* 失败对象；
* 失败阶段；
* 错误原因；
* 推荐处理方式；
* traceId 或日志入口。

示例：

```text
文档向量化失败：当前 ChatDoc 凭证不可用。请到「网关中心 → 知识向量化」重新测试连接后重试。traceId: http_20260606_demo
```

### 4.5 数据刷新

以下数据需要支持主动刷新：

* 供应商健康状态；
* 文档解析 / 向量化状态；
* 资源审核队列；
* 运维指标；
* 调用日志；
* 用量统计。

长耗时任务不应伪造固定百分比。轮询失败时应显示真实失败状态或“状态同步失败”，保留重试入口。

## 5. `/admin/knowledge-base` — 知识大本营

### 5.1 页面定位

知识大本营是课程资料知识库建设与检索调试中心。

它只负责课程资料的上传、解析、切分、向量化、状态同步、检索测试和引用验证，不负责普通 Chat 模型配置，也不负责资源正文生成。

### 5.2 核心能力

知识大本营需要支持：

* 按课程或全局范围查看文档；
* 管理课程资料；
* 上传 PDF / TXT / MD 等资料；
* 校验上传类型、大小和重复文件；
* 选择解析方式和入库策略；
* 同步云端文档状态；
* 展示解析、切分、向量化和可问答状态；
* 查看原文、切片和引用来源；
* 在 PDF 原文工作台中使用章节目录、全文搜索、搜索历史、最近阅读页恢复、页码跳转、当前页书签和页面笔记定位教材内容，并可删除当前页笔记或导出全部页面笔记 Markdown；
* 对课程资料执行检索测试；
* 批量解析、抽取或向量化；
* 删除、还原和彻底删除资料。

### 5.3 页面内容

#### 5.3.1 课程选择与标题区

包含：

* 当前课程筛选；
* 全部资料 / 当前课程资料范围切换；
* 页面标题“知识大本营”；
* 说明文案：PDF / TXT / MD 提交云端知识库解析与向量化，支持检索调试、分段预览与引用验证；
* 上传文档按钮；
* 批量操作入口；
* 进入回收站按钮；
* 跳转网关配置入口。

#### 5.3.2 状态统计卡片

展示：

* 总文档数；
* 云端分段数；
* 可检索数量；
* 处理中数量；
* 待授权或待入库数量；
* 失败数量；
* 当前课程远端知识库状态；
* 最近一次同步时间。

#### 5.3.3 课程文档列表

字段包括：

* 文档名称；
* 文档类型；
* 所属课程；
* 来源；
* 云端文档 ID；
* 分段数量；
* 流水阶段；
* 解析方式；
* 耗时；
* 状态；
* 错误摘要；
* 最近更新时间；
* 操作。

操作包括：

* 上传；
* 搜索；
* 来源筛选；
* 状态筛选；
* 查看文档；
* 查看分段；
* 查看抽取记录；
* 重新解析；
* 重新向量化；
* 删除；
* 检索测试。

#### 5.3.4 右侧工作区

右侧工作区用于查看和调试资料内容，建议包含三个 Tab：

```text
分段浏览 ｜ 检索测试 ｜ 处理记录
```

分段浏览展示：

* chunkId；
* 页码或位置；
* 分段正文；
* 向量状态；
* 引用元信息；
* 与章节或知识点的绑定关系。
* PDF 原文对照区：展示原文页、当前页切片、云端流水线状态和学习导航侧栏；学习导航包含目录、搜索、书签和笔记，搜索覆盖 PDF 文本索引和本地切片，搜索结果点击后跳转页码、选中切片并高亮命中文本；笔记区支持删除当前页笔记和导出全部页面笔记 Markdown。

检索测试展示：

* 查询输入框；
* 当前课程；
* 知识点范围；
* 检索模式：向量 / 混合；
* topN；
* 命中结果；
* 引用片段；
* 置信度；
* 云端响应耗时；
* traceId。

处理记录展示：

* 上传记录；
* 解析记录；
* 抽取记录；
* 向量化记录；
* 回调记录；
* 手动重试记录；
* 失败原因。

### 5.4 处理链路

```text
本地选择文件
  ↓
校验文件类型、大小、重复名称和课程权限
  ↓
系统保存 Document 记录
  ↓
CloudRagProvider.uploadDocument
  ↓
厂商云端 file/upload
  ↓
TEXT / OCR
  ↓
云端分段
  ↓
embedding / vectorize
  ↓
同步本地 DocumentChunk
  ↓
可检索 / 可问答
  ↓
状态回调或轮询同步
```

### 5.5 状态设计

| 状态 | 含义 | 用户侧影响 |
|---|---|---|
| uploaded | 已上传到系统 | 还不能问答 |
| remote_uploaded | 已上传到厂商云端 | 等待解析 |
| parsing | 解析中 | 课程资料问答不可用 |
| chunking | 分段中 | 课程资料问答不可用 |
| vectorizing | 向量化中 | 课程资料问答不可用 |
| ready | 可检索 / 可问答 | 课程资料问答可用 |
| failed | 处理失败 | 用户侧提示不可用 |
| deleted | 已删除 | 不参与检索 |

### 5.6 前置条件与失败处理

| 场景 | 处理方式 |
|---|---|
| 未选择课程上传课程资料 | 要求先选择课程或创建课程。 |
| CloudRagProvider 未配置 | 提示跳转网关中心配置知识向量化服务。 |
| 凭证测试失败 | 禁止继续上传到云端，展示失败原因和重测入口。 |
| 文档类型不支持 | 上传前拦截，展示支持格式。 |
| 文件重复 | 提示覆盖、重命名或取消。 |
| 云端解析卡住 | 显示 stuck 状态，允许同步状态或重试解析。 |
| 向量化失败 | 展示错误码、云端返回和重试入口。 |
| 回调失败 | 允许管理员手动轮询同步状态。 |

### 5.7 与用户侧联动

知识大本营的结果会影响：

* `/dashboard` 课程资料问答是否可用；
* `/dashboard` 基于课程资料生成是否可用；
* `/learning-path` 节点资源推荐；
* `/resource-hall` 课程资源沉淀；
* 运维舱 RAG 命中率和知识资产漏斗；
* 资源审核中的引用完整性判断。

## 6. `/admin/knowledge-base?panel=recycle` — 回收站

### 6.1 页面定位

回收站是知识大本营下的 panel，用于恢复误删课程和文档，也用于执行彻底删除。

### 6.2 页面内容

页面包含：

* 返回知识大本营；
* 页面标题“回收站”；
* 已删除课程列表；
* 已删除文档列表；
* 删除时间；
* 删除人；
* 删除原因；
* 影响范围；
* 还原；
* 彻底删除。

### 6.3 设计原则

* 误删课程和文档可以恢复；
* 彻底删除前必须二次确认；
* 文档彻底删除后，应同步删除本地记录与远端知识库引用；
* 删除课程前需要提示相关知识库、学习路径、资源、画像和用户会话关联影响；
* 彻底删除应写入审计日志；
* 删除失败时不能隐藏残留状态，应展示本地和云端的删除结果。

### 6.4 删除影响提示

删除课程前应提示：

```text
该课程关联学习路径、课程画像、知识库文档、资源任务、已保存资源和调用日志。删除后用户侧将无法继续按该课程学习。请确认是否删除。
```

彻底删除文档前应提示：

```text
彻底删除后该文档不再参与课程资料问答，相关引用片段可能失效。该操作不可撤销。
```

## 7. `/admin/model-gateway` — 网关中心

### 7.1 页面定位

网关中心用于统一管理 Chat 模型供应商、Cloud RAG / 文档问答供应商、课程绑定、用量统计、调用日志和健康状态。

### 7.2 核心原则

网关中心必须明确拆分：

```text
ChatProvider：负责普通对话和资源生成。
CloudRagProvider：负责课程资料上传、向量化、检索和文档问答。
```

两类供应商可以来自同一厂商，也可以来自不同厂商，但系统内部必须作为两种能力分别登记、分别检测、分别绑定。

CloudRagProvider 不能替代 ChatProvider。只配置 CloudRagProvider 时，课程资料问答可在知识库就绪后运行，但普通对话和资源生成仍不可用。

### 7.3 顶部状态卡片

* Chat 供应商数量；
* Chat 已启用数量；
* Chat 健康正常数量；
* Cloud RAG / 知识向量化配置状态；
* 当前课程绑定状态；
* 今日调用次数；
* 今日失败数；
* 今日 Token；
* 估算费用。

当 Chat 供应商为 0、Cloud RAG 已配置时，页面需要提示：

```text
当前只配置了课程资料问答 / 云端 RAG，尚未配置 Chat 模型。普通对话和资源生成不可用。
```

### 7.4 模块侧边栏

```text

图片生成
知识向量化
按课绑定
意图路由
调用日志
```

网关中心采用左侧模块侧边栏，不再使用顶部横向 Tab。侧边栏应呈现模块图标、名称、简短说明和关键状态徽标；右侧为当前模块的工作区。当前模块使用中性黑白高亮态，避免科技蓝大屏、渐变卡片或营销页风格。

### 7.7 按课绑定模块

课程绑定字段：

```ts
interface CourseAiBinding {
  courseId: string
  chatProviderId?: string | null
  cloudRagProviderId?: string | null
  remoteKnowledgeBaseId?: string | null
  defaultAnswerMode: 'default_chat' | 'course_rag_qa'
  allowRagFallbackToChat: boolean
  requireCitationForCourseAnswer: boolean
  defaultUseCourseEvidenceForResource: boolean
  isEnabled: boolean
}
```

页面需要展示：

* 当前课程；
* Chat 模型绑定；
* Cloud RAG 绑定；
* 远端知识库 ID；
* 知识库是否就绪；
* 默认回答模式；
* 未命中文档时是否允许回退普通 Chat；
* 课程资料问答是否必须有引用；
* 资源生成是否默认使用课程资料依据；
* 绑定启用状态。

保存绑定时需要校验：

* `defaultAnswerMode = course_rag_qa` 时必须绑定 CloudRagProvider；
* 启用课程资料问答时必须存在远端知识库 ID；
* `requireCitationForCourseAnswer = true` 时，课程资料问答不得返回无引用答案；
* 未绑定 ChatProvider 时，资源生成和普通 Chat 应提示不可用。

* 是否有未发布草稿。

配置项包括：

* 意图名称和显示名；
* 意图说明；
* 正例 utterances；
* 负例 negative utterances；
* 执行阈值；
* 澄清阈值；
* top1/top2 margin；
* 风险等级；
* 适用页面或入口；
* 默认响应 route；
* 允许动作；
* 是否启用。

操作包括：

* 可视化新增、编辑、删除意图；
* 批量编辑正例和负例；
* YAML 原文编辑；
* 从文件重新加载；
* 保存草稿；
* 校验配置；
* 运行离线评测；
* 发布生效；
* 回滚上一版本；
* 导入 / 导出 YAML；
* 预热或刷新样例 embedding；
* 查看本次变更对应的调用日志和审计日志。

当前 `/admin/model-gateway` 已提供 `tab=intent` 的“意图路由”模块。模块通过 `/api/v1/admin/intent-router/config` 系列接口读取和治理同一份 Intent Registry，页面包含：

* 左侧网关侧边栏：Chat 模型、图片生成、知识向量化、按课绑定、意图路由和调用日志入口；
* 顶部状态：活跃路径、活跃版本、草稿状态、校验状态、embedding 预热状态和意图启用数量；
* 趋势面板：以中性黑白图表展示意图优先级、样例覆盖和最近评测状态；
* 可视化编辑：以 Outline 数据表选择意图，右侧检查器编辑显示名、说明、启用状态、阈值、风险等级、响应 route、允许动作、适用页面、正例、负例和规则短语；
* YAML 原文编辑：直接维护 Registry 原文；
* 操作按钮：从文件重载、校验、评测、保存草稿、发布、回滚、导入和导出；
* 校验与评测结果：展示 schema 错误、precision、recall、false positive、false negative、clarification rate 和高风险误触发。

配置文件要求：

```text
backend/app/services/ai/intent/examples.yaml
  → 仓库内置默认配置和结构说明

storage/intent-router/intent_registry.yaml
  → 运行时活跃配置，路径可通过 INTENT_ROUTER_REGISTRY_PATH 覆盖
```

保存与发布规则：

* 后台表单和 YAML 原文编辑必须使用同一个 schema 校验器；
* 发布前必须校验字段类型、意图枚举、阈值范围、重复样例、空样例和高风险意图配置；
* 发布前必须运行最小离线评测，展示 precision、recall、false positive、false negative 和高风险误触发；
* 校验失败时不得覆盖当前已生效配置；
* 发布成功后触发 IntentRouter 热重载、样例 embedding 预热和缓存刷新；
* 所有保存、发布、回滚、重新加载文件和导入导出操作必须写入审计日志；
* Intent Registry 中不得保存 API Key、Secret、Token，云端 Embedding 和 LLM Judge 凭证仍在 Chat 模型 / 知识向量化配置中管理。

直接编辑文件规则：

* 开发者可以直接编辑 `INTENT_ROUTER_REGISTRY_PATH` 指向的 YAML 文件；
* 管理端提供“从文件重新加载”按钮，将磁盘文件读入、校验、评测并发布；
* 容器化部署时活跃配置文件应挂载到可写卷，不应依赖写入镜像内代码目录；
* 如果文件编辑导致 YAML 解析或 schema 校验失败，系统继续使用上一份有效配置，并在页面显示错误行列和字段名。

## 8. `/admin/resource-review` — 资源审核

### 8.1 页面定位

资源审核用于审核用户提交到资源大厅或社区的资源，确保资源质量、引用完整性、版权风险和安全合规。页面必须使用后端真实接口驱动审核队列、统计、详情、操作结果和审核日志，不再保留前端演示工作台数据。

### 8.2 审核对象

审核对象包括：

* 用户保存后提交的课程资源；
* 用户提交到社区的通用资源；
* 多智能体生成的资源；
* 管理员标记为精选前的候选资源；
* 因引用不足或安全审查异常进入人工复核的资源。

### 8.3 统计区

统计区来自 `GET /api/v1/admin/resources/review/stats`，包含：

* 待审核；
* 需修订；
* 今日通过；
* 精选资源；
* 引用缺失；
* 安全拦截。

统计口径必须与审核队列一致：引用缺失按资源引用数量或引用完整性结果计算，安全拦截按安全状态、驳回或隐藏状态计算，精选资源同时兼容资源状态和社区审核状态。

### 8.4 审核队列

审核队列来自 `GET /api/v1/admin/resources/review`，支持课程和状态筛选。字段包括：

* 资源标题；
* 类型；
* 范围：课程 / 通用；
* 关联课程；
* 知识点；
* 提交人；
* 质量分；
* 是否基于课程资料；
* 引用状态；
* AI 初检状态；
* 状态；
* 提交时间。

队列应采用左侧列表 + 右侧详情的高密度工作台布局，顶部只保留页面标题、真实接口说明和刷新入口。统计区、队列区和详情区在宽屏下应稳定对齐，避免把所有内容堆在单列演示卡片中。

### 8.5 筛选

支持：

* 全部；
* 待审核；
* 需修订；
* 已通过；
* 已拒绝；
* 精选资源；
* 资源类型；
* 课程；
* 知识点；
* 质量分；
* 引用状态；
* 提交人；
* 安全状态。

### 8.6 审核详情

详情区通过 `GET /api/v1/admin/resources/review/{resource_id}` 读取，不能只复用队列摘要。详情区需要展示：

* 资源正文；
* 资源 outline；
* 资源类型和生成参数；
* 用户编辑记录；
* 引用来源；
* 引用覆盖率；
* 画像使用摘要；
* AI 初检结果；
* 安全审查结果；
* 生成 trace；
* 历史版本；
* 审核日志。

审核日志通过 `GET /api/v1/admin/resources/review/logs` 或 `GET /api/v1/admin/resources/review/{resource_id}/logs` 读取，至少展示动作、审核人、审核状态、质量分、引用完整性、安全状态、操作时间和审核意见。

### 8.7 审核操作

管理员可以：

* 通过；
* 驳回；
* 要求修改；
* 标记精选；
* 隐藏；
* 归档；
* 查看引用；
* 查看 AI 初检；
* 查看生成 trace；
* 写入审核日志。

审核动作必须要求填写或自动生成审核意见：

| 操作 | 审核意见要求 |
|---|---|
| 通过 | 可选，记录质量评价。 |
| 驳回 | 必填，说明拒绝原因。 |
| 要求修改 | 必填，说明需要修改的内容。 |
| 标记精选 | 可选，说明推荐理由。 |
| 隐藏 | 可选，记录隐藏原因。 |
| 归档 | 可选，记录归档原因。 |

审核动作通过 `POST /api/v1/admin/resources/review/{resource_id}` 提交。成功后必须同步刷新：

* 审核统计；
* 审核队列；
* 当前资源详情；
* 审核日志；
* 资源大厅聚合数据。

质量分必须限制在 0 到 100，要求修改和驳回必须填写审核意见。

### 8.8 生命周期

```text
用户生成资源
  ↓
ArtifactCanvas 保存资源
  ↓
提交资源大厅 / 社区
  ↓
进入 pending_review
  ↓
AI 初检：格式、引用、安全、质量
  ↓
管理员审核
  ├─ 通过：进入可复用资源池
  ├─ 精选：进入可复用资源池并在资源大厅精选区展示
  ├─ 要求修改：退回用户编辑
  ├─ 驳回：不可公开展示
  ├─ 隐藏：从公开资源流移除
  └─ 归档：保留审计记录但不再参与大厅分发
```

### 8.9 质量判断

资源审核至少检查：

* 是否符合资源类型格式；
* 是否覆盖目标知识点；
* 是否存在明显事实错误；
* 题目答案与解析是否一致；
* 代码实验是否包含运行步骤和依赖说明；
* 基于课程资料生成时是否带引用；
* 引用是否覆盖关键结论；
* 是否存在版权、隐私或安全风险；
* 是否适合进入资源大厅复用。

* 供应商健康检测；
* WebSocket 连接状态；
* 资源任务队列状态。

### 9.6 云端知识资产漏斗

```text
已上传
  ↓
已解析
  ↓
已切分
  ↓
向量化
  ↓
可检索 / 可问答
```

漏斗需要支持按课程和供应商筛选，用于定位某门课程资料为什么不能问答。

### 9.7 告警与事件

包含：

* RAG 命中率低；
* 引用覆盖不足；
* Chat 模型不可用；
* 模型用量过高；
* AI 对话倍率偏高；
* 资源生成失败过多；
* 云端文档卡住；
* WebSocket 连接异常；
* 审核积压；
* 近期事件列表。

### 9.8 告警处理

告警应有状态流转：

```text
open
  ↓
acknowledged
  ↓
resolved / ignored
```

每次处理需要记录：

* 处理人；
* 处理时间；
* 处理说明；
* 关联 traceId；
* 是否需要后续跟进。

## 10. `/admin/course-builder` — 课程建设台

### 10.1 页面定位

课程建设台用于课程大纲、章节、知识点和课程图谱编排，为学习路径、知识库绑定和资源生成提供课程结构基础。

### 10.2 功能范围

功能包括：

* 课程基本信息；
* 课程大纲；
* 章节管理；
* 知识点管理；
* 知识元素；
* 前置关系；
* ReactFlow 图谱；
* 文件上传入口；
* 知识点和资源绑定；
* 未归类切片挂载；
* 保存课程结构；
* 课程图谱编排。

### 10.3 页面结构

建议结构：

```text
课程选择与课程状态
  ↓
课程基本信息
  ↓
章节与知识点树
  ↓
知识图谱画布
  ↓
章节资源 / 未归类草稿箱
```

课程状态需要提示：

* 是否存在课程资料；
* 文档解析数量；
* 向量就绪数量；
* 学习路径是否已生成；
* 是否存在未归类切片。

### 10.4 课程结构输出

课程建设台输出的数据会被以下模块使用：

* `/learning-path`；
* `/admin/knowledge-base`；
* `/dashboard` 课程上下文；
* ResourceAgent；
* 学情画像；
* 资源大厅；
* 运维舱课程维度统计。

### 10.5 保存规则

保存课程结构时需要校验：

* 课程标题不能为空；
* 章节顺序必须稳定；
* 知识点必须绑定章节；
* 前置关系不得形成循环；
* 删除章节前应提示关联知识点、资源和学习记录；
* 图谱节点变化应同步影响学习路径生成。

## 11. `/admin/announcements` — 公告发布

### 11.1 页面定位

公告发布用于管理员维护面向学生、管理员或全体用户的系统公告。公告可以以顶部条、弹窗、Toast、页面卡片或仅列表形式展示，并在用户侧 `/announcements` 与顶部导航未读角标中生效。

### 11.2 功能范围

功能包括：

* 公告统计：总数、草稿、已发布、已归档、已删除、生效中、严重公告和未读总数；
* 公告列表：按状态、关键词、展示类型、受众角色、优先级、分类筛选；
* 创建与编辑：标题、摘要、Markdown 正文、分类、优先级、展示类型、受众、置顶、可关闭、是否需要确认、自动关闭秒数、行动按钮和生效 / 过期时间；
* 生命周期操作：保存草稿、发布、归档、软删除；
* 详情预览：按用户侧展示方式检查标题、摘要、正文和行动入口。

### 11.3 发布规则

公告发布必须满足：

* `published` 且处于生效时间窗口内的公告才会进入用户侧可见列表；
* `audience_role` 控制学生、管理员或全体用户可见范围；
* `priority = critical` 或 `maintenance` 的公告应在用户侧以更高视觉优先级展示；
* `require_confirmation` 的公告需要用户点击确认后才算已读；
* `dismissible = false` 的公告不能被用户关闭展示；
* 归档和删除不应物理删除用户阅读记录。

## 12. `/admin/interface-settings` — 界面设置

### 12.1 页面定位

界面设置用于维护登录页视觉配置，当前重点是登录背景媒体和画面参数。该能力面向管理员，用户侧登录 / 注册页通过公开接口读取最终配置。

### 12.2 登录背景配置

配置项包括：

* 是否启用自定义背景；
* 媒体类型：图片或视频；
* 媒体地址：站内路径或 `http(s)` 地址；
* 适配方式：`cover` 或 `contain`；
* 水平 / 垂直位置；
* 缩放、亮度、对比度、饱和度、模糊；
* 遮罩透明度；
* 背景不可用时的回退底色。

### 12.3 媒体资源库

管理员可以：

* 查看内置和服务器上传的登录背景媒体；
* 上传图片或视频作为登录背景；
* 在编辑页实时预览桌面端登录画面；
* 保存后立即影响 `/login` 和 `/register`。

媒体上传必须限制文件类型和大小，保存配置时只能接受站内路径或 `http(s)` 地址，避免把本地绝对路径或不可信协议写入公开页面。

## 13. `/admin/chatdoc-config` — ChatDoc 配置

### 13.1 页面定位

ChatDoc 配置用于管理云端 RAG / ChatDoc 集成能力。

定位：

* 知识大本营或网关中心的配置子入口；
* 负责 ChatDoc / 云端 RAG 的密钥和连接配置；
* 可通过知识大本营中的 setup 参数或网关配置跳转；
* 不负责普通 Chat 和资源生成。

如果系统已经在 `/admin/model-gateway` 中完整支持 CloudRagProvider 配置，则 `/admin/chatdoc-config` 可以作为兼容入口或快捷配置页，并重定向到：

```text
/admin/model-gateway?tab=knowledge
```

### 13.2 配置内容

配置内容包括：

* 供应商模板；
* AppId；
* API Key；
* API Secret；
* endpoint；
* 默认知识库；
* 回调地址；
* 上传限制；
* 解析策略；
* 连接测试。

### 13.3 安全原则

* 密钥只允许写入，不允许明文回显；
* 测试连接失败时展示厂商错误摘要，不展示完整签名材料；
* 删除配置前应提示相关课程知识库将不可用；
* 配置变更后应触发网关重载或健康检测；
* 配置操作必须写入审计日志。

## 15. 安全与数据治理

### 15.1 密钥安全

* API Key、Secret、Token 不得硬编码在代码中；
* 管理端输入密钥后应加密存储或交由安全密钥管理服务；
* 前端不得缓存完整密钥；
* 日志、trace、导出 CSV 中不得包含完整密钥；
* 删除供应商配置时应清理关联密钥引用。

### 15.2 数据隔离

* 课程资料按课程隔离；
* 普通用户只能访问自己被分配课程的数据；
* 管理员可以管理课程，但操作必须审计；
* 通用资源和课程资源需要区分 scope；
* 课程资料问答不得在无课程状态下误用上一门课程知识库。

### 15.3 审核安全

资源审核需要关注：

* 用户隐私泄露；
* 版权风险；
* 不当内容；
* 幻觉引用；
* 课程资料引用缺失；
* 代码执行风险；
* 面向未成年或教育场景的不适宜内容。

## 16. 管理端验收标准

1. 非管理员访问 `/admin/*` 必须被重定向，不得展示管理数据。
2. 知识大本营只负责课程资料处理，不负责普通 Chat。
3. 网关中心必须分别配置 ChatProvider 和 CloudRagProvider。
4. 课程绑定必须区分 Chat 模型和 Cloud RAG 服务。
5. ChatProvider 未配置时，用户侧普通对话和资源生成不可用并有提示。
6. CloudRagProvider 未配置时，课程资料问答不可用，但普通 Chat 可用。
7. 知识大本营能展示文档上传、解析、向量化、可问答状态和失败原因。
8. 检索测试能返回命中片段、引用来源、置信度、耗时和 traceId。
9. 回收站能还原误删课程或文档，彻底删除前必须二次确认。
10. 网关中心能测试连接、查看健康状态、查看用量统计和调用日志。
11. 调用日志能按 traceId 定位供应商、能力类型、请求状态、错误码和耗时。
12. 调用日志能筛选 `intent_route` 和 `intent_feedback`，并展示意图、置信度、来源、候选项和反馈结果。
13. 网关中心能可视化编辑 Intent Registry，并支持 YAML 原文编辑、校验、评测、发布、回滚、导入导出和从文件重新加载。
14. 直接编辑 `INTENT_ROUTER_REGISTRY_PATH` 指向的 YAML 文件后，管理员能在后台触发重新加载；校验失败时继续使用上一份有效配置。
15. Intent Registry 不得保存 API Key、Secret、Token，所有配置发布、回滚、文件重载和导入导出必须写入审计日志。
16. 资源审核能通过真实接口查看资源内容、引用状态、AI 初检、版本、生成 trace 和审核日志。
17. 资源审核通过、驳回、要求修改、标记精选、隐藏和归档必须写入审核日志。
18. 资源审核动作完成后必须同步刷新审核统计、队列、详情、日志和资源大厅聚合数据。
19. 运维监控能区分 Chat 成本、Cloud RAG 成本、意图路由日志和资源生成成本。
20. 运维监控能展示 RAG 命中率、知识资产漏斗、供应商健康和告警事件。
21. 课程建设台能维护课程大纲、章节、知识点和图谱关系。
22. 删除课程、删除文档、修改供应商、修改课程绑定等关键操作必须写入审计日志。
23. 管理端所有长耗时任务必须展示真实阶段和失败提示，不得使用固定假进度。
24. 密钥、Token、Secret 不得明文回显或出现在导出日志中。
25. 管理端所有关键操作失败后必须给出明确错误原因、处理建议和重试入口。
26. 公告发布能创建、编辑、发布、归档和删除公告，并按受众、优先级、展示类型控制用户侧可见性。
27. 界面设置能上传或选择登录背景媒体，保存后登录 / 注册页通过公开配置实时生效。
