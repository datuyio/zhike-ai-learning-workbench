## 1. 项目概述与技术定位

智课 AI 个性化学习工作台是面向高等教育场景的 **AI 个性化学习闭环系统**：以 AI 对话为主入口，把课程上下文、知识库 RAG、学习路径、多层学情画像、多智能体资源生成与资源沉淀串成「对话 → 测评 → 纠偏 → 画像 → 生成」的持续进化飞轮。

产品的核心技术定位可概括为：

> **「私有化 · 可进化 · 可信」的 AI 学伴大脑** —— 本地微调大模型 + 本地向量库 + 本地混合检索实现可全离线私有部署的推理与问答；对话驱动的画像与资源生成形成持续进化闭环；检索拒答、引用核验、结构化校验构筑零幻觉可信防线。

系统同时覆盖三类角色、三个业务入口：

| 端 | 面向用户 | 核心能力 |
|---|---|---|
| 学生端 | 学习者 | AI 对话、课程资料问答、学习路径、学情画像、练习评估、资源大厅、作业/测验/日程 |
| 助教端（TA Portal） | 教师/助教 | 班级管理、作业布置与 AI 批改、随堂测验、AI 备课、学情诊断、预警干预、资源审核 |
| 管理端 | 平台管理员 | 知识大本营、模型网关、资源审核、运维监控、课程建设台、公告发布、界面设置 |

系统规模：三端口 **36 个页面**、**262 个 REST 端点**、**2 条 WebSocket 通道**、**82 张数据表**、**60 个数据库迁移**，全链路真机验证通过。

## 2. 总体技术架构

系统采用「前后端分离 + AI 编排分层 + 可插拔模型网关 + 本地推理微服务」的分层架构：

```text
┌─────────────────────────────────────────────────────────────┐
│  前端层  React 18 + TypeScript + Vite + Tailwind CSS         │
│  学生端 / 助教端 / 管理端（36 页面，SPA + 子路径部署）          │
└──────────────────────────┬──────────────────────────────────┘
                           │ HTTP / WebSocket（Vite 代理 5173 → 8001）
┌──────────────────────────▼──────────────────────────────────┐
│  业务 API 层  FastAPI + Pydantic v2（262 REST 端点 + 2 WS）    │
│  auth / courses / ai / resources / profile / ta / admin ...  │
└──────────────────────────┬──────────────────────────────────┘
┌──────────────────────────▼──────────────────────────────────┐
│  AI 编排层  AiOrchestratorService / TaAgentOrchestrator      │
│  HybridIntentRouter · ProfileContextResolver                 │
│  ChatService · CourseRagQaService · ResourceAgent ·          │
│  SafetyService · VerifyService · TraceService                │
└───────────────┬──────────────────────────┬──────────────────┘
                │                          │
┌───────────────▼──────────────┐  ┌────────▼──────────────────┐
│  Provider / Adapter 层        │  │  模型网关 ModelGateway     │
│  ChatProvider ↔ 多厂商 Adapter │  │  供应商链 · 健康检查 ·      │
│  CloudRagProvider ↔ 本地/云端  │  │  候选降级 · 预算 · 调用日志  │
│  RAG / ChatDoc Adapter        │  │  8 个供应商（含本地 LoRA）  │
└───────────────┬──────────────┘  └────────┬──────────────────┘
                │                          │
┌───────────────▼──────────────────────────▼──────────────────┐
│  基础设施层                                                    │
│  PostgreSQL 16 + pgvector（512 维向量）· Valkey/Redis         │
│  Ollama（Docker + GPU，本地 LoRA 推理）· 代码沙箱（Node+Pyodide）│
└─────────────────────────────────────────────────────────────┘
```

**分层职责边界**（关键设计原则）：

- **前端不直接判断调用哪个厂商 API**，只提交业务动作与上下文，由后端编排层统一调度；
- **Adapter 只做协议适配，不做业务意图判断**，供应商差异被隔离在适配层；
- **普通对话 / Agent 能力（ChatProvider）与课程资料问答 / 文档问答能力（CloudRagProvider）彻底解耦**，避免知识库 API 越权承担对话大脑职责；
- 所有 AI 调用写入 trace，**可追踪、可观测、可回放、可审计**。

### 3.4 选型原则

- **优先复用市场主流、成熟、活跃维护的方案**（FastAPI、React、LangGraph、pgvector 等），自研代码聚焦业务逻辑、流程编排、数据适配与安全规则，避免重复实现已有生态基础能力；
- **AI 能力不绑定单一厂商**：通过统一 Adapter 协议兼容 DeepSeek、通义千问、讯飞星火、智谱、OpenAI-compatible 等多家模型，云端 API 与本地模型互为降级；
- **开源合规**：所有引入的开源组件遵循其许可证（MIT / Apache-2.0 等），语料仅入库允许再分发的开源内容。

## 4. 核心 AI 技术支撑

### 4.1 统一 AI 编排与能力解耦（AiOrchestratorService）

用户侧所有 AI 请求（HTTP `/api/v1/ai/messages` 与 WebSocket `/ws/ai/{conversation_id}` 共用同一套编排）统一由 `AiOrchestratorService` 调度，按「显式模式 → 课程绑定 → 画像上下文 → 能力可用性」决策链路路由到 Chat、课程 RAG 或多智能体资源生成，保证 HTTP 与 WebSocket 行为一致、可审计。

### 4.2 混合意图路由（HybridIntentRouter）

将「我要学」「我学到哪了」「课件里怎么定义 X」「根据我的薄弱点出题」等自然语言请求路由到开始学习、学习计划、学习进度查询、课程资料问答、资源生成、默认对话等意图，不是单一关键词分类器，而是**可插拔、可评测、可审计的学习意图调度中枢**：

```text
显式 mode / actionType / intentType
  > 课程上下文、权限、风险等级等业务规则
  > 高精度业务规则
  > 上一轮 route / clientContext 短追问上下文
  > Intent Registry + semantic-router 语义召回
  > 可选 LLM Judge 结构化判别
  > 置信度校准、低置信度澄清与灰度策略
  > 默认 Chat
```

- 语义候选优先通过 `semantic-router` 召回，不可用时降级为 Embedding 余弦相似度，再降级本地轻量相似度，**多级降级保证路由不中断**；
- 路由结果写入 `intent_route` 日志、用户纠错写入 `intent_feedback` 日志，支持离线评测（脚本输出准确率/precision/recall）、阈值灰度与错误案例治理；
- 管理后台支持 Intent Registry 的可视化编辑、校验、评测、发布、回滚与导入导出。

### 4.3 多智能体协同资源生成（LangGraph）

系统采用**多角色智能体图工作流**（LangGraph 编排）协同完成个性化资源生成，满足赛题"多智能体架构"要求：

- **角色分工**：规划（依据画像与需求制定大纲）→ 取证（检索课程知识库获取依据）→ 生成（按角色产出内容）→ 核验（校验结构、事实与格式）→ 安全（内容安全过滤）→ 保存（版本化入库），全流程以 Inspector 面板可视化呈现；
- **资源类型**：高白话讲义、专业课程讲解文档、知识点思维导图、阶段测评题、错题补救卡、PyTorch/代码实操案例、拓展阅读包、PPT 大纲、视频/动画脚本、实践项目材料等 10 类；
- **任务化异步执行**：ResourceTaskCard 展示生成进度（创建 → 执行中 → completed），避免长时间白屏等待，满足赛题"生成进度追踪"非功能要求；
- **画布式产物**：ArtifactCanvas 支持预览、编辑、保存，并导出 Markdown / DOCX / PPTX / 浏览器打印 PDF / 思维导图 SVG / PNG 多模态格式；
- **课程依据可溯源**：课程内资源生成默认先检索课程知识库获取依据，未命中可靠依据时降级为 ChatProvider 直接生成并明确标记，**绝不伪造引用**。

### 4.4 本地知识库与混合检索 RAG

在保留讯飞 ChatDoc 云端 RAG 的同时，构建了可配置的**全本地知识库链路**（当前演示环境启用）：

```text
PDF / Markdown 语料 → 分块 → BGE-small-zh-v1.5 Embedding（512 维）
  → PostgreSQL pgvector 向量入库（24170 条切片）
  → BM25（jieba 分词）+ pgvector 余弦相似度 混合检索
  → 课程资料问答 / 资源生成依据 / 教师端知识检索
```

- 语料覆盖 7 条课程主线、1165 份本地文档、24170 个可检索切片（嵌入状态 ready 全覆盖）；
- 本地 Embedding 模型权重随仓库分发（`backend/storage/models`），**可全离线运行，不依赖外网**；
- 混合检索实测 **61ms** 命中真实知识片段，首次含模型加载约 11.2s（一次性），后续稳定毫秒级；
- RAG 查询日志记录命中/未命中（实测 19 条：命中 13 / 未命中 6），支撑检索质量持续优化。

### 4.5 多层动态学习画像

学习画像按作用范围分层，避免无课程对话污染具体课程画像：

```text
全局画像（专业背景/长期目标/认知风格/学习节奏/资源偏好/能力短板）
课程画像（当前掌握度/学习节点/易错点/测评表现/补救建议）
会话画像（当前主题/任务意图/临时目标/上下文来源）
跨课程画像（共性短板/前置知识影响/迁移能力）
```

- **对话式自动构建**：通过自然语言对话抽取特征，替代传统表单，随学随新（学习事件驱动增量更新，实测 94 条学习事件、37 条画像证据）；
- 每个画像维度携带**来源、更新时间、置信度**，支持证据链回溯与纠偏入口；
- 画像上下文由 ProfileContextResolver 在每次 AI 请求前解析注入，直接支撑个性化资源生成与路径规划。

### 4.6 学科垂类微调模型（QLoRA + 本地部署）

针对赛题"前沿 AI 技术融合"，团队完成 **Qwen2.5-7B-Instruct 学科垂类微调**并全链路接入系统：

| 环节 | 关键数据 |
|---|---|
| 训练数据 | 5 本经典 AI/ML 教材（PRML、周志华《机器学习》、李航《统计学习方法》、花书、Deep Learning Notes）构造 **7053 条 QA 对**，0 解析失败 / 0 重复 |
| 训练方法 | QLoRA 4-bit NF4 量化（~4.5GB 显存），LoRA r=8 / alpha=16 / dropout=0.05，可训练参数 **2018 万（仅 0.264%）** |
| 训练环境 | WSL2 + RTX 5060 8GB + PyTorch 2.10 + CUDA 12.8，1 epoch / 838 步 / 13h21m |
| 训练效果 | Loss 3.572 → 1.730（**-51.6%**），验证 loss 1.701 < 训练 1.933，梯度范数稳定，无过拟合 |
| 部署方式 | 基座 GGUF + f16 LoRA 适配器经 llama.cpp 合并，Ollama（Docker + GPU）提供 OpenAI 兼容接口，**支持流式输出** |
| 系统集成 | 注册为模型网关供应商 `qwen25-lora-ollama`（healthy），绑定深度学习课程 `deep_learning_001`，调用全链路写入 `model_call_logs` 可观测 |
| 推理性能 | 纯推理 **2.7s / 92 tokens**（~34 tokens/s），显存占用 ~4.4GB，8GB 消费级显卡可跑 |

**效果评估（17 题 5 领域 × 三轨评测）**：人工评测全部正确；自动指标（BLEU-4/ROUGE-L/TF-IDF 余弦）双向互评；LLM 裁判盲评（DeepSeek 裁判、隐去模型名、temperature=0）中 LoRA 总分 **16.12/20** 高于基座 15.71，简洁性维度大幅领先（4.76 vs 3.00）。结论：在作业辅导/快速问答场景下**微调收益成立**，回答风格从"百科式长篇"（基座 300 tokens 截断）转为"教材 QA 式精炼"（87 tokens 自然结束）。

### 4.7 教师端教学智能体（Function Calling + 人机确认）

助教端提供有身份、能聊天、能布置任务的对话式 Agent（TaAgentOrchestratorService）：

- **只读工具直接执行**：查班级、查学生、查作业、检索题库、查测验、查课程、检索本地知识库；
- **写操作人机确认**：布置作业、发布作业、创建测验、发布公告等写工具由模型提出工具名与参数，后端落待确认记录并暂停，**教师确认后才真正执行**——模型不得绕过后端产生副作用；
- **知识证据不足明确拒答**，与学习端共享零幻觉防线。

## 5. 安全可信技术支撑

### 5.1 结构化输出与工具调用纵深防御

所有机器消费的大模型输出（画像抽取、资源大纲、阶段测评题、AI 评分、推荐解释、审核初检、多智能体阶段结果、工具参数等）执行生产级五层治理链路：

```text
提示词约束 → API 格式约束 → 后端代码校验 → 输出修复/重试 → 标准化失败与降级
```

- **提示词约束**：明确字段含义、完整 JSON 示例、边界场景与输出禁令，结构化任务降低温度；
- **API 格式约束**：供应商支持 `response_format` / JSON Schema / Function Calling 时优先启用，不退化到仅靠自然语言提示；
- **后端代码校验**：Pydantic/JSON Schema 校验语法、类型、枚举、层级与业务规则，**校验通过前不得写库、不得展示为可评分题单、不得触发副作用**；
- **输出修复/重试**：校验失败把错误字段回传模型按同一 schema 修复，重试次数/超时可配置；
- **标准化降级**：连续失败返回稳定错误码与可重试状态，**不把不可解析结果伪装成成功**；
- 供应商不支持强结构化输出时显式记录能力缺口，并启用更严格的后端解析与降级。

**工具调用安全模型**遵循「模型提出、后端裁决、服务执行」边界：工具名、参数 schema、权限范围、副作用等级由后端注册表定义；写库/上传/通知/删除等副作用工具校验登录态、权限、幂等键、限流与超时；模型返回参数不直接拼接 SQL/路径/Shell/URL；高风险工具低置信意图必须先澄清。

### 5.2 零幻觉防线

- **检索拒答**：RAG 未命中可靠依据时不编造，明确拒答或降级（实测 `rag_guardrail_refused` 事件与"请选择课程后使用课程资料问答"优雅降级）；
- **引用核验**：知识问答返回引用来源（message_citations 35 条），课程资料问答的引用可溯源；
- **结构化校验**：生成内容经 Schema 与业务规则校验后才进入可评分/可展示/可审核状态；
- **内容安全过滤**：多智能体工作流内置安全审查节点，管理端资源审核双通道（管理员 + 助教）兜底。

### 5.3 权限与鉴权体系

- **三角色 RBAC**：管理员 / 助教 / 学生，管理端、助教端、学生端互不越权，实测越权用例 6/6 正确拦截（403/401）；
- **认证安全**：JWT + Argon2id 密码哈希，JWT 密钥与加密密钥强制高强度（弱密钥拒绝启动）；WebSocket 鉴权仅在 CONNECTING 状态执行 accept，不在 URL 传长期 token；
- **密钥管理**：API Key、数据库口令、JWT 密钥全部走环境变量，代码与前端页面不硬编码明文口令，管理员密码经环境变量种子初始化。

## 10. 技术亮点与创新总结

1. **全链路私有化部署**：本地微调大模型（QLoRA）+ 本地向量库（pgvector）+ 本地混合检索（BM25 + 向量）实现**可全离线运行**的 AI 学习系统，不依赖云端 API 也能完整演示核心闭环，超越同类"云端 API 套壳"产品；

6. **零幻觉可信防线**：检索拒答 + 引用核验 + 结构化输出五层纵深防御 + 工具调用"模型提出、后端裁决、服务执行"安全模型；
