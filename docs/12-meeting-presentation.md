# 第一部分：为什么选择计算机与人工智能学科

## 1.1 学科选择背景

我们参加的是科大讯飞发榜的赛题：

> **"面向一流学科建设的学科垂类大模型与创新应用开发"**

选择「计算机科学与人工智能」作为聚焦学科，基于以下三个核心考量：

### ① 团队优势最大化

| 考量因素 | 我们的情况 | 评估 |
|---------|-----------|------|
| 团队专业背景 | 全员计算机/AI 相关专业 | 天然匹配 |
| 现有知识积累 | 已有的课程资料以 CS/AI 为主 | 素材现成 |
| 技术理解深度 | 对 ML/DL/NLP 有扎实基础 | 无需额外学习成本 |

### ② 比赛评分最有利

| 评分维度 | 满分 | 选择 CS+AI 的原因 |
|---------|:----:|------------------|
| 技术先进性（10分） | 10 | 学科大模型微调 + 多智能体编排适配 CS/AI 领域 |
| 技术实现度（20分） | 20 | 代码沙箱、AI 编程辅导是本学科天然特色 |
| 内容质量度（20分） | 20 | CS/AI 领域有最丰富的开放教材、论文、开源项目 |

### ③ 演示效果最有冲击力

- **代码沙箱**：现场写代码、运行、AI 纠错 — 评委直观感受
- **多智能体可视化**：Agent 工作流时间线，展示技术深度
- **多模态输出**：文字 + 代码 + 图解混合展示，内容丰富

# 第四部分：工作流程与规范

## 4.1 代码协作流程

**队员开发流程：**
1. git pull origin develop — 拉取最新代码
2. git checkout -b feat/xxx/yyy — 创建功能分支
3. 开发 + 本地测试
4. git add . + git commit -m "feat(xxx): ..."
5. git push origin feat/xxx/yyy
6. 在 GitHub 创建 Pull Request → target: develop

**队长审查流程：**
1. 收到 PR 通知
2. 检查代码质量、安全性、风格
3. 通过则合并到 develop
4. 不通过则反馈修改意见

**合并后：**
所有队员 git pull origin develop 同步最新代码

## 4.2 分支命名规范

| 分支前缀 | 使用者 | 示例 |
|---------|--------|------|
| feat/backend/ | 队员b | feat/backend/code-sandbox |
| feat/frontend/ | 队员c | feat/frontend/sandbox-ui |
| feat/backend-ta/ | 副队长d | feat/backend-ta/grading-api |
| feat/frontend-ta/ | 队员e | feat/frontend-ta/diagnosis |
| feat/docs/ | 成员f | feat/docs/system-manual |
| feat/docs-aux/ | 成员g | feat/docs-aux/test-cases |
| fix/ | 任何人 | fix/login-error |

## 4.3 核心规则

**规则一：禁止直接 push develop** — 所有代码必须走 PR + 审查

**规则二：API 契约先行** — 前端不等后端，先约定 API 格式，用 Mock 数据开发

**规则三：每日站会** — 每天 15 分钟，回答：昨天做了什么？今天做什么？有什么阻塞？

**规则四：代码审查** — 每条 PR 检查：正常运行、符合风格、中文注释、无敏感信息
